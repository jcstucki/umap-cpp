## c01_chain_eucl upd0_emb/upd1_emb — CLASS (a) REAL BUG [PROVEN]
**Claim under test:** update() faithful. **Observed:** upd0/upd1 embeddings totally diverge (max_abs ~9) while fit/transform/inverse/graph/rho/sig are all BITEXACT.
**Root cause (exact):** epoch-count resolution inside update().
- Upstream (reference/umap/umap/umap_.py:3494ff): `update()` sets `n_epochs = 0` when `self.n_epochs is None`, and passes 0 to `simplicial_set_embedding`. There (umap_.py:1131ff) only `None` is mapped to default_epochs (`if n_epochs is None:`); the 0 survives -> `make_epochs_per_sample(graph.data, 0)` returns all -1 -> `optimize_layout_euclidean` runs `for n in range(0)` = ZERO epochs. Upstream update() with default n_epochs performs NO optimization: the result is exactly the [0,10]-rescaled init (old embedding + init_update mean-neighbor rows).
- C++ (snapshot src/umap.cpp:3049-3052): `requested_epochs = params_.n_epochs.value_or(-1)`; `resolve_epochs_and_filter_graph` (src/layouts.cpp:571) maps <0 -> default_epochs (500 for n<=10000) -> runs 500 SGD epochs. The code comment "0 -> the 500/200 default" misstates upstream; NOT a documented deviation (author believed it faithful).
**Proof (bit-exact, both directions):**
1. Python-side zero-epoch proof: predecessor probe /tmp/umap-audit/min/pyupd_eps1.npy (update's epochs_per_sample) is ALL -1.0, and pyupd_sgdinit1.npy (rescaled init handed to SGD) == ref_upd0_emb bit-exactly.
2. C++-side 500-epoch proof: /tmp/umap-audit/c01probe/force500.py — fit c01 in Python (matches ref_emb bit-exact), then set `m.n_epochs = 500` before each update: result == cpp_upd0_emb AND == cpp_upd1_emb BIT-EXACTLY. The only divergence in the whole update path is the epoch count; graph rebuild, init_update, rescale, SGD, and rng usage are bit-faithful.
**Severity:** moderate-high. Any model with unset n_epochs gives a completely different (fully re-optimized) embedding after update() vs upstream (which returns the un-optimized rescaled init -- arguably an upstream bug, but faithfulness is to behavior). Masked in the repo test suite because all update goldens pin n_epochs explicitly.
**Minimal repro:** case /tmp/umap-audit/cases/c01_chain_eucl (flags: --n-neighbors 12 --seed 42 --init random --a 1.55 --b 0.85, upd0/upd1, NO --n-epochs) + c01probe/force500.py.

**Trigger scope:** target_metric="count" with y whose tmean is not exactly representable in the y dtype (any non-degenerate f32 y). "ordinal" is immune (support_size=(max-min)/2 exact for integer-valued y -> c06 BITEXACT). f64 y input would match by construction.

**Mechanism:** upstream transform's small-data kNN uses NUMPY np.argpartition (introselect) + argsort (umap_.py:3199-3216); the C++ transform reuses fast_knn_from_dmat, the port's replication of NUMBA's median-of-3 quickselect (correct for fit, where upstream uses numba fast_knn_indices -- fit knn is BITEXACT even here). **Classification:** (a) real behavioral deviation, LOW severity (choice among exactly-equidistant neighbors; embedding quality equivalent). The code comment at src/umap.cpp:2225 ("argpartition + argsort: k smallest per row ... ties by ascending index") overclaims equivalence with numpy's introselect.
